# 실제 macOS Dock 오버레이: 프로토타입과 합의 제안

현재 단계는 요청한 작업 순서의 **1단계**입니다. 본 앱은 아직 기존 자체 Dock 모드입니다.
아래 실행 파일은 본 앱과 독립적으로 실행되며 `DockmanController`/`DockPanel`을 생성하지 않습니다.
ConfigStore나 설정 JSON 스키마, AppActivityMonitor, 기존 도시 그래픽은 변경하지 않습니다.

## 검증하는 두 가지

1. 실제 `com.apple.dock` 프로세스의 AXList 직계 자식에서 AXPosition/AXSize와 원시 role/subrole을 읽습니다.
2. 아이콘 영역을 포함하는 투명 비활성 NSPanel을 올리고 클릭/드래그/우클릭이 실제 Dock으로 통과하는지 사람이 확인합니다.

AXList 탐색은 깊이/노드 수를 제한하고 AX 호출은 150ms 타임아웃을 사용합니다.
200ms 기본 폴링은 직렬로 실행되어 중첩 호출이 쌓이지 않으며 AppKit 메인 스레드를 차단하지 않습니다.
역할/하위 역할로만 앱·구분선·휴지통을 분류합니다. 지역화된 제목으로 분류하지 않습니다.
좌표가 없거나 Dock이 구분선·휴지통을 노출하지 않으면 누락된 그대로 출력합니다.
어떤 항목이 누락됐는지 사람이 실제 Dock과 대조해야 합니다. `--once`의 종료 코드 0은
일부 유효한 AX 좌표를 읽었다는 뜻이며 두 검증 목표 전체의 성공을 의미하지 않습니다.

프로토타입은 코드로 도시를 그리지 않고 **실제 아이콘 테두리 + 안쪽으로 뻗는 중심선 + 항목 번호/종류**를 표시합니다.
도시 렌더러와 Dock 추적 문제를 섞지 않고 좌표와 입력 통과를 먼저 확인하기 위한 진단 도구입니다.

## Mac에서 실행

먼저 기존 Dock City를 메뉴에서 종료하세요. 실제 macOS Dock은 그대로 둡니다.
프로토타입은 Dock 설정을 읽기만 하며 Dock을 종료·재시작하거나 숨김 설정을 변경하지 않습니다.

```bash
swift build --jobs 4
swift test --jobs 4
./scripts/make-app.sh probe release
open 'build/Dock City Overlay Probe.app'
```

별도 Bundle ID는 `com.metaparodica.DockCity.overlayProbe`입니다.
접근성 권한이 없으면 안내 대화상자만 표시하고 도시 오버레이나 대체 Dock은 띄우지 않습니다.
안내에서 Request access를 누른 뒤 시스템 설정의 개인정보 보호 및 보안 → 손쉬운 사용에서
이 앱을 승인하세요. 필요하면 앱을 다시 실행합니다. `Dock Probe` 메뉴에서 종료할 수 있습니다.
코드가 바뀌어 ad-hoc 서명도 바뀐 경우 시스템 설정에서 기존 승인 항목을 다시 확인해야 할 수 있습니다.
이 프로토타입은 권한 부여를 자동화하지 않습니다.

좌표 JSON을 터미널에서 확인하려면 동일한 패키지 안의 실행 파일을 사용하세요.
다른 Swift 빌드 바이너리를 사용하면 TCC가 다른 실행 주체로 취급할 수 있습니다.

```bash
'build/Dock City Overlay Probe.app/Contents/MacOS/dock-city-overlay-probe' --once
'build/Dock City Overlay Probe.app/Contents/MacOS/dock-city-overlay-probe' --log-changes --interval 0.2 --level 21
```

첫 명령은 창을 만들지 않고 한 번 읽어 출력합니다. 두 번째는 대화형 오버레이와 변화 로그를 표시합니다.
두 개를 동시에 실행하지 마세요. 입력 정보는 로컬 진단용 표준 출력뿐이며 파일 저장이나 외부 전송은 없습니다.
읽는 정보는 Dock 항목의 역할·제목·사각형 및 Dock 프로세스의 창 사각형/레벨입니다.
다른 앱의 화면 내용·파일·키보드·오디오를 수집하지 않습니다.

종료 코드: `--once`에서 0 = 일부 유효 좌표 존재, 2 = 접근성 권한 없음,
3 = Dock 프로세스 없음, 4 = 읽기 실패·불완전 결과·유효 좌표 없음, 64 = 잘못된 인자.

## Mac에서 기록할 결과 — 아직 미검증

| 항목 | 확인 방법 | 통과 조건 |
| --- | --- | --- |
| 앱 좌표 | JSON axFrame/cocoaFrames와 청록 테두리 | 실제 앱 아이콘과 정확히 일치 |
| 구분선 | raw role/subrole 및 itemKinds | 실제 구분선 항목/좌표 확인; 미노출이면 미검증으로 보고 |
| 휴지통 | 분홍 테두리, AXTrashDockItem | 실제 휴지통과 정확히 일치 |
| 클릭 통과 | 테두리 위에서 앱 클릭 | 실제 앱이 열리거나 활성화됨 |
| 드래그 | 실제 Dock 아이콘 재정렬 | 정렬 가능하고 테두리가 새 위치로 이동 |
| 우클릭 | 테두리 안에서 우클릭 | 실제 macOS Dock 메뉴 표시 |
| 겹침 순서 | 보고서 dockWindowLayer/observedOverlayLevel | 기본 레벨 Dock+1에서 테두리가 Dock에 가려지지 않음 |
| 같은 레벨 비교 | 종료 후 `--level 20`으로 다시 실행 | 가려짐 여부를 21 결과와 대조; 사람 확인 전 보장하지 않음 |
| 확대·크기 | 기존 사용 환경에서 확대/축소 | 폴링이 실제 크기·중심 변화에 따라감 |
| 자동 숨김 | Dock 표시/숨김 | 좌표가 화면 밖으로 나가면 오버레이 숨김; AX가 낡은 좌표를 주면 한계로 기록 |
| 여러 화면 | Dock을 다른 화면에 표시 | 해당 화면으로 패널 이동, 음수 좌표도 정렬 |
| 권한 철회 | 시스템 설정에서 권한 해제 | 오버레이가 사라지고 안내 상태로 전환 |

AX/CG 좌표를 주 화면의 maxY 기준으로 Cocoa 좌표로 변환하며 Retina 배율을 곱하지 않습니다.
`.canJoinAllSpaces`는 이번 실험의 표시 정책이며 본 구현의 전체화면·Spaces 정책 확정은 별도입니다.
본 프로토타입의 설정된 `ignoresMouseEvents=true`는 실제 클릭 통과의 실험 증거를 대체하지 않습니다.
CG 창 정보에 접근할 수 없으면 관측 레벨이 null일 수 있으며 화면 녹화 권한을 새로 요청하지 않습니다.

## 2단계 합의 제안 — 아직 적용하지 않음

- 본 앱의 기본 모드를 **실제 macOS Dock 오버레이**로 전환합니다.
- 기존 자체 Dock은 삭제하지 않고 **설정에서 명시적으로 선택하는 대체 모드**로 보존합니다.
- 접근성 권한이 없으면 안내 화면을 보여 줍니다. 사용자가 선택하지 않은 자체 Dock으로 자동 전환하지 않습니다.
- 실제 Dock 모드는 기존 앱 상태 모니터·도시 렌더러·ConfigStore를 재사용하지만 자체 Dock의 앱 실행·드래그·메뉴 경로는 시작하지 않습니다.
- 모드 필드는 기존 설정에 없으면 하위 호환 기본값을 적용하는 디코딩/마이그레이션과 함께 도입합니다. 기존 설정 파일을 무조건 전환하지 않습니다.

요청에서 기존 모드 유지/삭제를 합의 후 진행하도록 지정했으므로, 이 선택과 프로토타입 실험 결과가 확인되기 전에는 본 구현으로 전환하지 않습니다.

## 시각 개선 1~6의 후속 제안 — 아직 적용하지 않음

1. 야간 외벽을 일괄 남색으로 만드는 현재 경로를 수정해 11개 스킨의 색조를 유지합니다. 미지정 앱은 Bundle ID의 고정 해시로 높이·폭·색·옥상 변주를 만듭니다(Swift Hasher의 실행마다 달라지는 seed는 사용하지 않음).
2. 시민과 차량의 실루엣·크기를 키우고 좁은 Dock에서는 밀도를 줄입니다. 실제 가시성을 보고 기본 수를 결정합니다.
3. 도시와 Dock 사이에 작은 여백과 부드러운 그림자를 둡니다.
4. 스킨별 지붕/높이와 미지정 앱의 결정적 변주를 합쳐 스카이라인을 바꿉니다.
5. AX에서 검증된 구분선 위치에 광장/보행 공간을 만듭니다. AX 미노출일 때의 대체 계산은 별도 검증 없이 사실로 취급하지 않습니다.
6. 배경은 **반투명 하늘을 기본, 완전 투명을 옵션**으로 제안합니다. 현재 그래픽은 변경하지 않았습니다.
